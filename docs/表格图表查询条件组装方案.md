# 表格 / 图表查询条件组装方案（设计备忘）

> **状态**：**部分实现**（`com.example.pptrefresh.query` 包：ReportingContext、QueryPlan、维度提取与条件解析；已接入编排与 Prompt）。  
> **任职以来默认口径**（§6.1.1）：有主基金经理 → 用主基金经理任职日；否则 → **现任基金经理中任职日较早者**（`EARLIEST`）；可选 deck 配置 `LATEST`。  
> **背景**：当前 `TimeRuleResolver` 仅产出全局 `latestDate`、`latestQuarter`，Tool 入参无法表达「近一年」「近二年」等**模板行标题**或柱图/折线图**横轴刻度**所隐含的真实区间。  
> **目标**：在调用 Tool **之前**，从 PPT 模板**读出维度标签** → 按 deck 规则**解析为可查询条件** → 组装为结构化 **QueryPlan** 传给 LLM/接口。  
> **相关**：[字段化刷新与全页文本方案](./字段化刷新与全页文本方案.md)、[Tool约束与注册方案](./Tool约束与注册方案.md)、[`ppt-data-refresh-design.md`](./ppt-data-refresh-design.md)。

---

## 1. 问题陈述

### 1.1 现状

| 组件 | 行为 |
|------|------|
| `timeRules: [latestQuarter, latestDate]` | 全 deck 共用一个 `TimeContext` |
| `TaskContext` | 带 `fundCode`、`productDisplayName`、`timeContext`、`SlideStructure`（行列数） |
| Tool 调用 | 多数只传 `latestQuarter` 或 `latestDate` + `dimensions` |

### 1.2 不足

1. **收益率表**（示例：行标题「近一年 / 近两年 / 近三年」）  
   接口需要的是：**相对报告截止日的起止日期**（如 `2025-05-19`～`2026-05-19`），而不是一个 `latestQuarter`。

2. **资产配置柱图**（横轴 `2024Q2`…`2025Q1`）  
   需要：从模板读出**已有季度标签** → 以 `asOf` 为锚**向前滚动** → 窗口内只保留 **4 个季度** 写回（模板可能旧了，要「延伸再截取」）。

3. **净值折线图**（横轴常为月份 `2024-05`…）  
   需要：从模板或规则得到**点数、粒度（月/季）** → 生成**截止日往前 N 个点**的查询区间列表。

4. **加工规则因 deck / task 而异**  
   不能写死在 Java；应在 **YAML + 可插拔解析器** 中声明。

## 2. 设计原则

1. **模板驱动维度**：查询什么，由 PPT 里**已经展示的标签**（表首列、图 categories）决定，而不是写死「永远查近 3 年」。
2. **报告锚点 asOf**：所有相对区间（近一年、滚动四季度）相对同一个 **`asOfDate` / `asOfQuarter`** 计算（可与文件名、标题「数据截止」或配置对齐）。
3. **先解析、后取数**：`DimensionExtractor` → `ConditionResolver` → `QueryPlan` → Tool；LLM 负责选 Tool 时**参数已备好**，减少幻觉。
4. **写回形状与模板一致**：解析阶段记录「模板要的行数/列数/点数」；取数后校验；窗口截取后 **categories 与 cells 行序一一对应**。
5. **可测试**：给定 asOf + 模板标签快照 → 期望 QueryPlan 固定（单元测试不依赖 LLM）。

## 3. 核心概念

### 3.1 报告锚点（AsOf）

| 字段 | 说明 | 来源（优先级建议） |
|------|------|-------------------|
| `asOfDate` | 数据截止日（LocalDate） | ① deck 配置 `asOf: filename` / `asOf: today` ② 标题解析 ③ 默认今天 |
| `asOfQuarter` | 截止所在「报告季」（如 `2025Q1`） | 由 `asOfDate` 推导或配置覆盖 |
| `fundInceptionDate` | 基金成立日（解析「成立以来」用） | `FundFactsClient` 按 `fundCode` 查询（当前 Stub 固定值；YAML 可 override） |
| `managerTenureStartDate` | 现任基金经理任职起点（解析「任职以来」用） | fund_meta 结构化字段 / 接口 / 约定文本 |

与现有 `TimeContext` 关系：可视为 **扩展** `TimeContext` → `ReportingContext`（保留 `latestDate/latestQuarter` 别名兼容）。

### 3.2 维度标签（Dimension Label）

从模板**读出**的原始字符串，例如：

- 表：`近一年`、`近两年`、`近三年`、`成立以来`、**`任职以来`**
- 图：`2024Q2`、`2024Q3`、`2024Q4`、`2025Q1`
- 图：`2024-05`、`2024-07`…（月频）

### 3.3 查询条件（Query Condition）

机器可执行的区间描述，建议统一结构：

```json
{
  "kind": "DATE_RANGE | QUARTER_RANGE | MONTH_RANGE | SINCE_INCEPTION | SINCE_MANAGER_TENURE | CUSTOM",
  "startDate": "2025-05-19",
  "endDate": "2026-05-19",
  "startQuarter": "2024Q2",
  "endQuarter": "2025Q1",
  "label": "近一年",
  "inclusiveEnd": true
}
```

不必一次全填；按 `kind` 使用对应字段。

### 3.4 查询计划（QueryPlan）

**每个 table/chart task 一份**，调用 Tool 前生成：

```json
{
  "taskId": "yield_ranking_table",
  "asOfDate": "2026-05-19",
  "asOfQuarter": "2025Q1",
  "dimensions": [
    { "slotIndex": 0, "role": "header", "label": "区间", "condition": null },
    { "slotIndex": 1, "role": "data_row", "label": "近一年", "condition": { "kind": "DATE_RANGE", "startDate": "2025-05-19", "endDate": "2026-05-19" } },
    { "slotIndex": 2, "role": "data_row", "label": "近两年", "condition": { "kind": "DATE_RANGE", "startDate": "2023-05-19", "endDate": "2026-05-19" } }
  ],
  "writeBack": {
    "tableRows": 4,
    "tableCols": 4,
    "categoryLabels": null
  }
}
```

图表类 `writeBack.categoryLabels` 为**最终要写回的**横轴标签（窗口截取后最多 4 个季度）。

## 4. 总体流程

```
打开 PPT 副本
    │
    ▼
ReportingContext（asOfDate / asOfQuarter）
    │
    ▼
对每个 table/chart task：
    │
    ├─► DimensionExtractor：从目标表/图读取标签
    │       · 表：第 1 列数据行（跳过表头）
    │       · 图：categories（嵌入表 A 列或 chart strCache）
    │
    ├─► ConditionResolver：标签 + asOf + task 规则 → QueryCondition[]
    │       · 规则表：近N年、滚动季、月频等
    │
    ├─► WindowPolicy（可选）：截取/补齐到模板形状
    │       · 季图：向前延伸后只保留 4 季
    │       · 表：行数必须与模板一致
    │
    └─► QueryPlan → 写入 TaskContext / Prompt / Tool 参数
            │
            ▼
        LLM 选 Tool（或流水线直调）→ 接口按 condition 取数
            │
            ▼
        WritePayload 校验行列/点数与 writeBack 一致 → POI 写回
```

**要点**：LLM **不应**自行推算「近一年」的起止日；Java（或配置化规则引擎）算好，Tool 只消费 `QueryPlan`。

## 5. 维度提取（DimensionExtractor）

### 5.1 表格（yield_ranking_table 类）

模板表格**不固定**：布局不再在 YAML 配 `labelAxis` / `labelIndex` / `headerSpan`。

| 步骤 | 说明 |
|------|------|
| 定位 | `tableOrdinal` |
| 读矩阵 | `TableMatrixReader` 读出全文 |
| LLM 意图 | `intervalLabels` + `metrics`；可选 `intervalAxis`（ROW/COLUMN）；**不算日期、不猜行列下标** |
| Java 布局 | `TableMatrixLayoutResolver` 在矩阵中定位各区间标签：全在同一行→COLUMN，全在同一列→ROW；与 LLM 的 axis 不一致时 **warn，以矩阵为准** |
| 解析条件 | 词表 `lexicon` → `IntervalConditionResolver` 得到每条区间的 `QueryCondition` |
| 查数 | `QueryPlanDataService` 对每个 `interval × metric` 调数据接口 |
| QueryPlan | 简化为 `table.headers` / `table.metrics` / `table.intervals[].condition`（见 `QueryPlanFormatter`） |

**表头**（`区间`、`收益率`…）由推断结果写入 `role: header` 的 `columnHeaders`，不参与接口查询。

**YAML 示例**：

```yaml
dimensionPolicy:
  policyType: table_interval_labels
  lexicon: /rules/lexicon/fund_performance_rows.yaml
```

**异常**：标签为空、词表无法识别 → `DIMENSION_EXTRACT` / `LEXICON_UNKNOWN_LABEL`。

### 5.2 季度柱图（allocation_chart 类）

| 步骤 | 说明 |
|------|------|
| 定位 | `chartOrdinal` |
| 读 categories | 优先 chart `strCache` / 嵌入表 **A2:An**（季度列） |
| 解析季度 | 正则 `20\d{2}Q[1-4]`（兼容全角） |
| 输出 | 有序列表 `["2024Q2","2024Q3","2024Q4","2025Q1"]`（可能来自旧模板） |

注意：读的是**模板当前展示**的季度，不是「应该展示的」；滚动与截取在下一阶段。

### 5.3 净值折线图（nav_chart 类）

| 步骤 | 说明 |
|------|------|
| 读 categories | 月字符串 `yyyy-MM` 或 `yyyy年M月` |
| 输出 | 有序时间点列表 + 推断 `granularity=MONTH` |
| 点数 | `categoryCount` 与模板一致（示例 7 个点） |

若模板为季频则走 `QUARTER` 解析器分支（deck 配置 `categoryType: month | quarter`）。

## 6. 条件解析（ConditionResolver）

### 6.1 相对区间标签词典（表）

建议在 deck YAML 或全局 `rules/dimension-lexicon.yaml` 维护：

| 模板标签模式 | 条件类型 | 计算（相对 asOfDate） |
|--------------|----------|------------------------|
| `近一年` | DATE_RANGE | `[asOf - 1年 + 1日, asOf]` 或 `[asOf - 1年, asOf]`（需统一 inclusivity） |
| `近两年` | DATE_RANGE | asOf 往前 2 个周年 |
| `近三年` | DATE_RANGE | 3 年 |
| `近五年` | DATE_RANGE | 5 年 |
| `成立以来` | SINCE_INCEPTION | `startDate = fundInceptionDate`，`endDate = asOfDate` |
| **`任职以来`** | **SINCE_MANAGER_TENURE** | `startDate = managerTenureStartDate`，`endDate = asOfDate`（见下） |
| `今年以来` | DATE_RANGE | 当年 1/1 ～ asOf |
| `20\d{2}年` | CALENDAR_YEAR | 该自然年 1/1～12/31 与 asOf 取交集 |

#### 「成立以来」与「任职以来」

二者都是「起点固定、终点为 asOf」的区间，但**起点语义不同**，不可混用：

| 标签 | 起点 | 典型数据来源 |
|------|------|----------------|
| 成立以来 | 基金合同生效日 / 成立日 | `fund_meta` 中「成立日期」、主数据接口 |
| 任职以来 | **现任基金经理任职起始日**（若多基金经理取规则约定：最早/最晚/主基金经理） | `fund_meta`「基金经理」附带的任职日、人事/主数据接口 |

**任职日解析（实现时择一或组合）**：

1. **结构化字段**：刷新 `fund_meta` 时由接口返回 `managerTenureStart`（推荐，避免从「张明、李悦（示例）」反解析）。  
2. **文本解析**：从 PPT/规则锚点块解析「任职日期：yyyy-MM-dd」（需在模板或 YAML 中约定字段）。  
3. **接口按 fundCode 查询**：`GET /fund/{code}/manager-tenure` → 返回当前管托任职起点。

**边界**：

- 任职日晚于 asOf → 无效区间，task 失败或该行留空/降级。  
- 任职日早于成立日 → 一般 **截断到成立日**（与「近一年」遇成立日的处理一致）。  
- 基金经理变更但模板仍写「任职以来」→ 以**当前披露口径**的任职起点为准。

**默认约定（已采纳）**：

| 情形 | `managerTenureStartDate` |
|------|---------------------------|
| 有主基金经理（`LEAD`） | 主基金经理任职日 |
| 合管且未标主基金经理 | **现任基金经理中任职日较早者**（`reporting.managerTenureRule: EARLIEST`，默认） |
| deck 配置 `managerTenureRule: LATEST` | 现任基金经理中任职日较晚者（少数场景） |

**日历规则需产品确认**：

- 「近一年」是 **滚动 365 天** 还是 **最近 4 个季度** 还是 **12 个自然月**？
- 节假日、基金成立日晚于区间起点 → 截断到成立日。

未命中词典时：

- **策略 A**：task 失败，要求补充 lexicon  
- **策略 B**：交给 LLM 仅做「标签→条件」映射（输入 asOf + 标签，输出 JSON），Java 校验  
- **策略 C**：deck 级 `defaultRowCondition: rolling_1y`  

首期建议 **A + 少量高频词**；B 作兜底。

### 6.2 季度滚动与窗口（图）

目标：**最终只展示 4 个季度**，且以 **asOfQuarter** 为右端（最新完整季或报告季）。

**算法草案**：

```
输入：templateCategories（模板里读到的旧季度，可忽略或作格式参考）
      asOfQuarter（如 2025Q1）
      windowSize = 4（deck 配置）

1. end = asOfQuarter（或上一完整自然季，与 TimeRuleResolver 策略一致）
2. quarters = [end, prev(end), prev(end), prev(end)]  // 共 4 个
3. writeBack.categoryLabels = quarters
4. 对每个 quarter q：QueryCondition { kind: QUARTER_POINT, quarter: q }
```

**「往前延伸几个季度」** 的含义落地为：

- 接口查询时可多取 `end` 往前 **K 季**（K ≥ 4，如 K=8）用于校验或填充缺失；
- **写回 PPT 仍只取最后 4 季**（与模板柱数一致）。

若模板 categories 已是 4 个但过期（如仍显示 2023Q2…2024Q1）：

- **不以模板季度为查询范围**；
- 仅用模板推断 **个数 = 4** 与 **格式**；
- 标签由 `asOfQuarter` 重算后写回。

### 6.3 月份折线（nav_chart）

| 配置项 | 说明 |
|--------|------|
| `pointCount` | 来自模板 categories 个数（如 7） |
| `frequency` | `MONTH` |
| `end` | `asOfDate` 所在月或上月末（产品定） |

生成：`endMonth, endMonth-1, …` 共 `pointCount` 个月；每条 `MONTH_RANGE` 或单点 `asOfMonth` 供接口聚合收益率。

## 7. Deck / Task 配置扩展（YAML 草案）

在 task 或 deck 级增加 `dimensionPolicy`（名称待定）：

```yaml
timeRules:
  asOf:
    source: today          # today | filename_date | fixed
    # fixedDate: 2026-05-19

tasks:
  - id: yield_ranking_table
    type: table
    tableOrdinal: 1
    dimensionPolicy:
      policyType: table_interval_labels
      lexicon: /rules/lexicon/fund_performance_rows.yaml
      # 或 inline:
      # rowLabels:
      #   近一年: { rollingYears: 1 }
      #   近两年: { rollingYears: 2 }

  - id: allocation_chart
    type: chart
    chartOrdinal: 1
    dimensionPolicy:
      type: quarter_series
      windowSize: 4
      anchor: asOfQuarter       # 右端季度
      queryLookback: 8           # 接口可多查几季，写回仍 4
      categoryFormat: "yyyy'Q'Q"

  - id: nav_chart
    type: chart
    chartOrdinal: 2
    dimensionPolicy:
      type: month_series
      pointCountFromTemplate: true
      anchor: asOfDate
      frequency: MONTH
```

全局词典示例 `rules/lexicon/fund_performance_rows.yaml`：

```yaml
id: fund_performance_rows
entries:
  - match: "近一年"
    rollingYears: 1
  - match: "近两年"
    rollingYears: 2
  - match: "近三年"
    rollingYears: 3
  - match: "成立以来"
    kind: SINCE_INCEPTION
  - match: "任职以来"
    kind: SINCE_MANAGER_TENURE
    # startDate 由 ReportingContext.managerTenureStartDate 注入，非 rollingYears
```

## 8. 与 Tool / LLM 的衔接

### 8.1 Tool 入参演进（概念）

由「仅 latestQuarter」改为携带 **序列化 QueryPlan** 或扁平参数，例如：

```
fetchPerformanceTable(
  productCode,
  asOfDate,
  intervals: [
    { label: "近一年", startDate, endDate },
    { label: "近两年", startDate, endDate }
  ],
  expectedRows, expectedCols
)

fetchAllocationChart(
  productCode,
  quarters: ["2024Q2","2024Q3","2024Q4","2025Q1"],
  seriesCount
)
```

LLM **原样传递** `intervals` / `quarters`，不在对话中改日期。

### 8.2 PromptBuilder 增强

每个 table/chart task 的 user 消息增加块：

```
=== queryPlan (precomputed, do not recalculate dates) ===
{...json...}
```

并明确：模型只需选 Tool 并填 productCode；日期以 queryPlan 为准。

### 8.3 流水线模式（可选）

对 `yield_ranking_table` 配置 `tool: fetchPerformanceTable` 时，编排层 **直接调用** Tool，跳过 LLM 选参，进一步稳态。

## 10. 失败处理与校验

| 阶段 | 校验 |
|------|------|
| 提取 | 表至少 1 个数据行；图 categories 可解析 |
| 解析 | 每行标签均有 condition；`成立以来` 需成立日；**`任职以来` 需任职起点日** |
| 窗口 | 季图 windowSize 与 template categoryCount 一致或为配置覆盖 |
| Tool 返回 | cells 行数 = dimensions 数据行数；chart 点数 = categoryLabels.length |
| 写回 | 现有 `WritePayloadValidator` 扩展 |

失败阶段建议：`DIMENSION_EXTRACT`、`CONDITION_RESOLVE`、`QUERY_PLAN_BUILD`（写入 `.failed.json`）。

## 11. 分阶段落地

| 阶段 | 内容 |
|------|------|
| **P0** | `ReportingContext` 支持可配置 `asOf`；文档化「近一年」日历定义 |
| **P1** | 表：提取第 1 列标签 + lexicon 解析 DATE_RANGE；Tool 入参带 `intervals[]` |
| **P2** | 季图：`asOfQuarter` 滚动 4 季生成 categories；Tool 按 quarters 查询 |
| **P3** | 月图：按模板点数生成月序列；`成立以来` / **`任职以来`** 对接成立日、任职起点 |
| **P4** | 与 [字段化刷新与全页文本方案](./字段化刷新与全页文本方案.md) 合并：整页 QueryPlan 一次输出 |
