# PPT 产品名称（展示名）提取方案

> 说明刷新任务如何**从 PPT 内容**解析基金/产品**展示名**，再查**基金代码**并供后续 LLM、Tool 使用。  
> 实现类：`ProductNameResolver`、`ProductNameStrategy`；配置位于各 deck 的 YAML 顶层 `productNameResolution`。  
> 相关架构见 [`ppt-data-refresh-technical-architecture.md`](./ppt-data-refresh-technical-architecture.md)。

---

## 1. 为什么需要这一步

刷新 API **不要求**调用方传入 `productName`。编排流程在打开 PPT 副本后、执行各 `tasks` 之前会：

1. 按 **deck 规则**从幻灯片中解析 **产品展示名**（`productDisplayName`）；
2. 用展示名查询 **基金代码**（演示环境为 `HardcodedFundCodeLookup`，生产可换数据库）；
3. 将二者写入 **`TaskContext`**，供 `PromptBuilder`、Demo Tool、后续写回任务使用。

解析失败（且非 `EMPTY_OK`）时，任务在阶段 **`PRODUCT_NAME_RESOLVE`** 结束，并生成 `.failed.json`。

---

## 2. 配置位置与结构

每个 `deckType` 对应一份 `src/main/resources/rules/decks/*.yaml`，在 `tasks` 之前增加：

```yaml
productNameResolution:
  strategy: <策略枚举名>
  # 以下字段按策略选填，见第 4 节
```

| 字段 | 说明 |
|------|------|
| `strategy` | 必填，见第 3 节四种取值 |
| `slideIndex` | 单页下标（相对值，见第 5 节），默认 `0`；`ANCHOR_REGEX` / `LLM_EXTRACT` 均只解析该页 |
| `anchorText` | `ANCHOR_REGEX`：定位文本框的锚点字面量 |
| `pattern` | `ANCHOR_REGEX`：Java 正则，**第 1 捕获组**为展示名 |
| `hint` | `LLM_EXTRACT`：给模型的简短业务提示 |
| `literal` | `STATIC`：写死的展示名 |

加载时由 `RulesValidator` 校验必填项；非法策略或缺字段会在 **`RULES_SCHEMA`** 阶段失败。

---

## 3. 四种策略一览

| 策略 | 适用场景 |
|------|----------|
| `ANCHOR_REGEX` | 标题为「**可变前缀**-产品名」或其它固定版式，用锚点+正则抠名（**推荐**） |
| `LLM_EXTRACT` | 版式不统一、难以写死规则 |
| `EMPTY_OK` | 本 deck 不依赖产品名/代码 |
| `STATIC` | 联调、固定单只产品 |

策略枚举定义见：`com.example.pptrefresh.rules.ProductNameStrategy`。

> **说明**：产品名解析**不依赖**文件名第 2 段；文件名仅用于 `deckType` 路由与白名单（`段1-段2-段3.pptx`）。

---

## 4. 分策略说明与配置示例

### 4.1 `ANCHOR_REGEX`（推荐：前缀可变、形如 `xxx-yyy`）

**规则**

1. 在指定页找到**唯一**包含 `anchorText` 的文本框（与 text 任务锚点逻辑相同）。
2. 对该框**全文**执行 `pattern`，**第 1 个捕获组**为展示名。

**典型需求：标题为「任意前缀-产品名」，只取连字符后**

单行标题：

```yaml
productNameResolution:
  strategy: ANCHOR_REGEX
  slideIndex: 0
  anchorText: "产品一页通"    # 须为标题框内稳定、且全页唯一的字样
  pattern: "^[^-]+-(.+)$"     # 第一个 - 之后为产品名
```

文本框内多行、其中一行是 `前缀-yyy`：

```yaml
productNameResolution:
  strategy: ANCHOR_REGEX
  slideIndex: 0
  anchorText: "产品一页通"
  pattern: "(?m)^[^-]+-(.+)$"  # 多行模式：任一行匹配
```

**`anchorText` 选取建议**

- 不要用**会随产品变化的前缀**（如标题里的「偏债混」）作锚点。
- 优先用模板里**固定副标题、栏目标签**，或标题框内**产品名片段**（全页唯一时）。
- 若 `anchorText` 命中 0 个或多个文本框，报错 `ANCHOR_NOT_FOUND` / `ANCHOR_NOT_UNIQUE`。

**YAML（当前 `偏债混-M1.yaml` 样例）**

```yaml
productNameResolution:
  strategy: ANCHOR_REGEX
  slideIndex: 0
  anchorText: "瑾添"
  pattern: "^[^-]+-(.+)$"
```

样例标题 `偏债混-中欧瑾添` → 解析为 `中欧瑾添`（前缀 `偏债混` 可变，只要标题框仍含锚点且正则匹配）。

**正则说明**

- 使用 **Java 正则**（`Pattern`），捕获组从 **1** 开始计数。
- 中英文破折号若混用，可在字符类中同时写 `-` 与 `－`：`[^-－]+-(.+)`。

---

### 4.2 `LLM_EXTRACT`（版式难规则化）

将 **`slideIndex` 指定的那一页**的纯文本交给模型，调用一次**无 tools** 的短对话，要求**只输出一行**展示名（不跨页拼接）。

```yaml
productNameResolution:
  strategy: LLM_EXTRACT
  slideIndex: 0
  hint: "标题形如「任意前缀-产品名」，只输出连字符后的产品展示名，不要前缀、不要解释"
```

**前提**：`application.yml` 中 `ppt.refresh.llm.enabled: true` 且 API Key 可用。  
**特点**：适应性强；成本与不确定性高于正则。

---

### 4.3 `EMPTY_OK`（不解析产品名）

展示名与基金代码均为空字符串；后续任务与 Tool 自行处理（演示数据可能对空名兜底）。

```yaml
productNameResolution:
  strategy: EMPTY_OK
```

**示例 deck**：`混合固收+-M1.yaml`（占位/样例 deck）。

---

### 4.4 `STATIC`（写死展示名）

不读 PPT，直接使用 `literal`。

```yaml
productNameResolution:
  strategy: STATIC
  literal: "中欧瑾添"
```

适用于联调、或暂时无法从版式解析的场景。

## 5. 页码与 `slide-index-base`

规则里的 `slideIndex` 为**相对下标**，实际访问的幻灯片为：

```
实际页 = ppt.refresh.slide-index-base + slideIndex
```

| `slide-index-base` | 规则 `slideIndex: 0` 表示 |
|--------------------|---------------------------|
| `0`（默认） | 文件第 1 张 |
| `1` | 文件第 2 张（例如第 1 张为封面、规则仍从「内容第 1 页」记为 0 时） |

配置项位于 `application.yml` 的 `ppt.refresh.slide-index-base`。

---

## 6. 解析之后：基金代码

展示名解析成功后，调用 **`HardcodedFundCodeLookup.lookupFundCode(displayName)`**（演示；生产替换为数据库）。

- 展示名**非空**但查不到代码 → `FUND_CODE_NOT_FOUND`，阶段 `PRODUCT_NAME_RESOLVE`。
- `EMPTY_OK` 时展示名为空，不触发「非空却无代码」校验。

演示映射示例（可扩展 `putAlias`）：

| 展示名 | 基金代码 |
|--------|----------|
| 中欧瑾添 / 中欧瑾添A / 瑾添 | 013998 |
| 演示产品 | 019999 |

## 7. 与 API、文件名的关系

| 来源 | 作用 |
|------|------|
| 文件名 `段1-段2-段3.pptx` | 路由 `deckType`、段 2/段 3 白名单校验 |
| API 请求体 | **不含** `productName`，仅 `sourcePptxPath`、`outputPptxPath` |
| `productNameResolution` | 决定如何从 PPT 得到展示名 |

---

## 8. 选型建议（速查）

```
标题是「可变前缀-yyy」，且能选定稳定 anchorText？
  └─ 是 → ANCHOR_REGEX（pattern 取第一个 - 之后）

锚点难找、版式杂？
  └─ LLM_EXTRACT

本 deck 不需要产品名？
  └─ EMPTY_OK

固定一只产品联调？
  └─ STATIC
```

---

## 9. 常见错误码

| errorCode | 含义 |
|-----------|------|
| `MISSING_PRODUCT_NAME_RESOLUTION` | YAML 未配置 `productNameResolution` |
| `ANCHOR_NOT_FOUND` / `ANCHOR_NOT_UNIQUE` | 锚点定位失败 |
| `ANCHOR_REGEX_NO_MATCH` | 正则未匹配 |
| `LLM_EXTRACT_EMPTY_SLIDE` | 指定页无文本 |
| `LLM_DISABLED` | 策略为 LLM 但未开启 llm |
| `FUND_CODE_NOT_FOUND` | 有展示名但演示库无代码映射 |

失败报告字段：`productName`（展示名）、`fundCode`（若已解析到）。
