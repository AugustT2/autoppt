# 多产品名称提取方案

> **文档状态**：方案讨论稿；**表级多产品、按 task 分流等能力尚未实现**。  
> **当前实现范围**：仅 **单页单产品**（`PAGE_SINGLE`），见 [`产品名称提取方案.md`](./产品名称提取方案.md)。  
> 本文档描述业务上「一页一产品」与「一页一表多行多产品」并存时的目标架构，供后续迭代对齐。

---

## 1. 背景

实际业务中，同一类 deck（同一 `deckType`）里会同时出现：

| 版式 | 说明 | 产品名数量 |
|------|------|------------|
| **单页单产品** | 一页材料围绕一只基金：标题、业绩表、图表同属该产品 | 每页 **1** 个 |
| **单页多产品（表驱动）** | 一页一张表，多行每只基金一行（排名、对比等） | 每页 **N** 个（按行） |

二者对「何时解析产品名、如何查基金代码、如何传给 LLM/Tool」的要求不同，**不能用「整份 PPT 只解析一个 `productName`」一种模型覆盖**。

---

## 2. 核心概念：产品上下文（Product Context）

与「提取策略」（`ANCHOR_REGEX`、`LLM_EXTRACT` 等，见 [`产品名称提取方案.md`](./产品名称提取方案.md)）正交，增加 **产品上下文模式**：

| 模式 | 枚举（拟定） | 含义 |
|------|----------------|------|
| **页级单产品** | `PAGE_SINGLE` | 指定页解析 **1** 个展示名 + 1 个基金代码，供该页相关 task 共用 |
| **表级多产品** | `TABLE_MULTI_ROW` | 不在 deck 顶层解析唯一产品名；在 **table 类 task** 内按行读产品列、按行查码、按行写回 |

同一 deck 的 `tasks` 列表中，**不同 task 可声明不同 `productContext`**（后续实现）；未声明时默认 `PAGE_SINGLE`，与现状一致。

```
提取策略（ANCHOR_REGEX / LLM…）  →  「怎么从一个文本里抠出一个名字」
产品上下文（PAGE_SINGLE / TABLE…） →  「这个名字是页级共用还是表级按行」
```

---

## 3. 当前已实现：单页单产品（PAGE_SINGLE）

### 3.1 行为（与代码一致）

1. 加载 deck YAML 顶层 **`productNameResolution`**（策略 + `slideIndex` 等）。
2. 打开 PPT 副本后、执行 `tasks` **之前**，调用 `ProductNameResolver` 解析 **一个** `productDisplayName`。
3. `HardcodedFundCodeLookup`（演示）或后续数据库 → **一个** `fundCode`。
4. 所有 task 的 `TaskContext` 携带同一对 name/code（除非策略为 `EMPTY_OK`）。

### 3.2 配置入口

- 文件：`src/main/resources/rules/decks/*.yaml`
- 块：`productNameResolution`
- 详细策略与示例：[`产品名称提取方案.md`](./产品名称提取方案.md)

### 3.3 业务约定（已对齐）

- **一页对应一只产品**；产品名 **只从该页** 解析，**不跨页拼接**文本。
- API **不传** `productName`；文件名仅用于 `deckType` 与白名单，**不参与**「可变前缀-yyy」类标题匹配（已移除 `SEGMENT2_PREFIX_TITLE`）。
- 标题常见形态：`可变前缀-yyy`，推荐 `ANCHOR_REGEX` + 稳定 `anchorText` + `^[^-]+-(.+)$`。

### 3.4 局限（已知）

- 整次刷新任务 **只有一个** 全局 `fundCode`。
- 无法表达「第 2 页排名表 10 行 = 10 只基金」按行查码刷新的语义。

## 4. 目标能力：单页多产品（TABLE_MULTI_ROW）— 未实现

> 以下为目标设计，**代码与 YAML 字段均未落地**；实现前需结合真实表样再评审。

### 4.1 适用页面

- 一页 **仅一张关键表**（或 `tableOrdinal` 指定的那张表）。
- **数据行**（跳过表头）中，某一列为 **产品展示名** 或 **基金代码**。
- 各数据行指标需按 **该行产品** 调 Tool/接口 后写回同行其它列。

### 4.2 与 PAGE_SINGLE 的差异

| 维度 | PAGE_SINGLE（现状） | TABLE_MULTI_ROW（目标） |
|------|---------------------|-------------------------|
| 解析时机 | 全部 task 之前一次 | **进入该 table task 时** |
| 解析结果 | 1 个 name + 1 个 code | `List<行号, name, code>` |
| deck 顶层 `productNameResolution` | 必填（或 `EMPTY_OK`） | 通常 **不需要**；表 task 自带列配置 |
| LLM | 每 task 一次，带统一 fundCode | 可选：一次返回整张 `cells`，或 Java 按行调 Tool 填表 |
| 失败粒度 | 整 job 失败 | 需约定：整表失败 vs 单行失败 |

### 4.3 拟定 YAML 形态（示意）

```yaml
# deck 顶层：多产品表页可不配 productNameResolution，或 strategy: EMPTY_OK

tasks:
  - id: fund_overview_page
    productContext: PAGE_SINGLE          # 可省略，默认
    # productNameResolution: 继承 deck 顶层
    slideIndex: 0
    type: text
    ...

  - id: peer_rank_table
    productContext: TABLE_MULTI_ROW      # 【未实现】
    slideIndex: 1
    type: table
    tableOrdinal: 1
    productNameColumn: 0                 # 产品名列（0-based）
    dataRowStart: 1                      # 数据起始行（0 多为表头）
    # productCodeColumn: 可选，若名列已是代码则直接查数
    intent: "按行刷新排名表，每行一只基金"
```

### 4.4 拟定编排流程（示意）

```
对每个 task:
  if productContext == PAGE_SINGLE:
      若本页尚未缓存 → ProductNameResolver → (name, code)
      → 现有 LLM + 写回链路

  if productContext == TABLE_MULTI_ROW:
      读表 dimensions
      → 遍历 dataRowStart..末行，读 productNameColumn
      → 每行 lookupFundCode（或批量接口）
      → 每行取数（Tool 或批量 Tool）
      → 组装 cells 写回（或按行写入）
```

### 4.5 实现前待确认（业务问卷）

1. 产品列是 **展示名** 还是 **带 A: 代码**？是否存在 **合计/备注行** 需要跳过？
2. 某行 **查码失败**：整表失败、跳过该行、还是写入 `.failed.json` 并带 `rowIndex`？
3. 取数：**每行一次 Tool** 还是 **`fetchTableByProductCodes([...])`** 一次返回多行？
4. 表级 task 是否仍走 LLM 生成整张 `cells`，还是 **Java + Tool 直填**（排名表建议后者，更稳定）？
5. 同页是否可能 **上半页单产品文案 + 下半页多产品表**？若会，则必须 **task 级** `productContext`，不能仅靠 deck 默认。

## 5. 两种版式在同一 deck 中共存

典型结构：

| 幻灯片 | 版式 | productContext |
|--------|------|----------------|
| 第 0 页 | 单基金一页通 | `PAGE_SINGLE` |
| 第 1 页 | 多基金排名表 | `TABLE_MULTI_ROW` |
| 第 2 页 | 单基金续页 | `PAGE_SINGLE`（可换 slideIndex / 解析规则） |

原则：

- **不要** 在 deck 顶层强行解析一个「全局产品名」去刷排名表。
- **单产品页** 继续用现有 `productNameResolution` + 该页 `slideIndex`。
- **多产品表页** 仅由标记了 `TABLE_MULTI_ROW` 的 table task 处理产品维度。

后续可选：支持 **task 级** `productNameResolution` 覆盖 deck 默认（同一 deck 两种单产品页、标题版式不同）。

## 6. 与现有模块的关系

| 模块 | PAGE_SINGLE（现状） | TABLE_MULTI_ROW（规划） |
|------|----------------------|-------------------------|
| `ProductNameResolver` | 已用 | 仅服务页级；表级另增「按行解析」或表读取器 |
| `TaskContext` | 单 name/code | 需扩展或 table task 内部上下文 |
| `HardcodedFundCodeLookup` | 单次 lookup | 按行多次或批量 lookup |
| `LlmTaskRunner` | 每 task 一次 | 表级可选不走 LLM |
| `WritePayloadValidator` | 校验整块 cells | 仍校验行列数；cells 由多行组装 |
| [`产品名称提取方案.md`](./产品名称提取方案.md) | **现行规范** | 页级策略仍以该文档为准 |
